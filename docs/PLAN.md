> هدف: ساخت کامل در **کمتر از ۱۰ ساعت کار ایجنت**، با یک ایجنت اصلی (Orchestrator) و چند ساب‌ایجنت موازی.
> روش اجرا (D10): بعد از تأیید مستندات کار یکسره اجرا می‌شود و **در پایان هر فاز commit، push و tag** انجام می‌شود.

## الگوی اجرا با ساب‌ایجنت‌ها

- **ایجنت اصلی** این کارها را **خودش** انجام می‌دهد: «قرارداد»ها (Prisma schema، schemaهای Zod در `packages/shared`، Interface استراتژی‌ها و tokenهای UI)، ادغام، اجرای تست‌ها، commit و push.
- **ساب‌ایجنت‌ها** فقط بعد از آماده شدن قرارداد و روی بخش‌های **بدون هم‌پوشانی فایل** کار می‌کنند. هر کدام در `isolation: worktree` و روی شاخه `phase/<n>/<slug>` کار می‌کند.
- هر ساب‌ایجنت یک brief دارد شامل هدف، فایل‌های مجاز برای تغییر، قرارداد (مسیر schemaها)، معیار پذیرش و دستور «قبل از پایان lint، typecheck و test را سبز کن». خروجی‌اش یک شاخه است با خلاصه تغییرات، تست‌های اضافه‌شده و موارد باز.
- ایجنت اصلی شاخه‌ها را **یکی‌یکی merge** می‌کند. بعد از هر merge تست کامل اجرا می‌شود و تعارض‌ها را خودش حل می‌کند.
- کار شبکه‌ای (`pnpm install`) و Docker فقط در ایجنت اصلی انجام می‌شود تا cache مشترک بماند.

## P1 — زیربنا (`v0.1.0`)

**ترتیبی (ایجنت اصلی):**
1. `git init`، اتصال به remote، `.gitignore` و `.env.example`، و commit مستندات (P0) و push.
2. اسکلت pnpm + Turborepo، شامل `apps/web`، `apps/api`، `packages/{shared,engine,ui}` و tsconfig/eslint/prettier مشترک.
3. **Prisma schema کامل** (SPEC §۲) با migration اولیه و SQL خام قیدها (unique partial، exclusion، triggerهای append-only).
4. `packages/shared`: enumها، کدهای خطا، توابع شمسی، اعتبارسنج‌های کد ملی، شبا و پلاک، و schemaهای Zod پایه.
5. `docker compose -f infra/docker/compose.dev.yml` شامل postgres و redis.

**موازی (۳ ساب‌ایجنت):**
| ایجنت | محدوده | پذیرش |
|---|---|---|
| A — API Core | NestJS bootstrap، ClockService، Prisma module، Auth (login، refresh چرخشی، logout، register-driver، تک‌نشست)، Guards نقش و scoping، Audit interceptor، Exception filter، throttler، helmet، health و metrics | تست‌های Auth، تک‌نشست، قفل حساب و ماتریس نقش‌ها سبز |
| B — UI Kit و پوسته‌ها | `packages/ui` (tokenها، فونت self-host و همه کامپوننت‌های GUIDELINES §۱.۳)، layoutهای factory، carrier و driver (هدر، سایدبار، Drawer و BottomNav)، صفحه login و register، و کلاینت API و `useServerClock` | Storybook-lite (`/dev/ui`)، بدون درخواست خارجی، RTL درست در ۳۶۰px و ۱۴۴۰px |
| C — DevOps | Dockerfileهای چندمرحله‌ای (non-root)، `compose.prod.yml`، Nginx (TLS و هدرها)، GitHub Actions `ci.yml` (با postgres و redis service) و gitleaks | CI روی push سبز |

**پذیرش P1:** ورود هر سه نقش با seed، داشبورد خالی هر پنل، و CI سبز. → commit، push و tag `v0.1.0`

## P2 — دامنه و پنل‌ها (`v0.2.0`)

**قرارداد (ایجنت اصلی):** schemaهای Zod همه منابع، پیکربندی ستون‌های اعلام بار و مجوز (SPEC §۲.۴)، و `DataTable` سمت سرور به‌همراه helper خروجی xlsx.

**موازی (۴ ساب‌ایجنت؛ هر کدام API + UI یک برش عمودی):**
| ایجنت | محدوده |
|---|---|
| D — کارخانه | باربری‌ها، سهمیه و کاربران باربری، سالن‌ها و برنامه هفتگی و hall_days، داده‌های پایه (مقاصد، بارگیر، بسته‌بندی، محصول)، Policyها (فرم نسخه‌بندی‌شده)، رانندگان (block)، فایل روزانه (آپلود)، Audit و نشست‌ها |
| E — اعلام بار | فرم ۷ بخشی (ثبت، ویرایش، کپی، کنسل)، جدول با همه ستون‌ها و انتخاب ستون، کنترل سهمیه (AC-11)، ایجاد load_units و تغییر نوع تخصیص (BR-10/11) |
| F — باربری (سایر) | داشبورد باربری، تأیید راننده، داده‌های پایه باربری (۵ جدول)، فایل روزانه (مشاهده و دانلود و seen)، فهرست مجوزها و اقدام‌های حضور، بارگیری، خروج و برگشت، و گزارش‌های مجوز صادره و تجمیع با Excel |
| G — راننده (غیرنوبتی) | ثبت‌نام، داشبورد (کارت مدارک، هشدارها، میان‌برها)، پروفایل (راننده، خودرو، رمز)، شرکت‌ها، ساعات اعلام بار، و PWA manifest و service worker |

**پذیرش P2:** سناریوی کامل «کارخانه باربری می‌سازد ← فایل روزانه ← باربری اعلام بار ۱۰ کامیونی ثبت می‌کند ← راننده ثبت‌نام می‌کند ← باربری تأیید می‌کند» به‌صورت دستی و با تست integration کار کند. IDOR suite برای endpointهای جدید سبز باشد. → `v0.2.0`

## P3 — موتور نوبت‌دهی (`v0.3.0`)

**ترتیبی، با TDD (ایجنت اصلی یا ایجنت H):**
1. `packages/engine`: `allocateBag()` و `planBulk()` / `stepBulk()` به‌صورت pure. **اول تست‌های مرجع** (چهار مثال سند فله، determinism و fast-check) نوشته می‌شوند و بعد پیاده‌سازی. پوشش ۱۰۰٪.

**موازی بعد از سبز شدن engine (۳ ساب‌ایجنت):**
| ایجنت | محدوده |
|---|---|
| I — Engine API | `QueueEngineService` و سه Strategy، مسیر رزرو اتمیک (SPEC §۳.۲)، ثبت نوبت و اولویت‌ها، Job تخصیص (BullMQ + lazy)، worker tick فله و advisory lock، لغو و جریمه، pub/sub و SSE، `queue_events`، و تست‌های هم‌زمانی (AC-2، AC-3، AC-5، AC-6، AC-7، AC-8) |
| J — UI راننده | سالن کیسه‌ای (شمارش معکوس، ثبت نوبت، انتخاب و drag سه اولویت، نتیجه)، سالن فله (گروه من، وضعیت پنجره، تایمر)، انتخاب بار (شهرها، فهرست، جزئیات، رزرو و تگ زنده «رزرو شده»)، رزروهای من و درخواست لغو، و سوابق |
| K — UI باربری و کارخانه | مدیریت گروه‌ها (افزودن سریع، اعضا، ترتیب، فعال‌سازی، گروه شروع)، تنظیمات چرخش، کنترل زنده فله (توقف و پایان زودهنگام)، صف لغوها، مانیتور کارخانه (پنجره‌ها و نتیجه Job)، و گزارش عدالت تخصیص فله |

**پذیرش P3:** همه ACهای ۱ تا ۱۰ با تست خودکار سبز باشند. یک روز کامل کیسه‌ای و یک روز کامل فله در محیط dev با seed قابل اجرا باشند (اسکریپت `pnpm demo:day` با FakeClock سریع). → `v0.3.0`
